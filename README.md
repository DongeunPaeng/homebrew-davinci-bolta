# davinci-bolta

볼타 API로 세금계산서를 발행하는 macOS CLI입니다. API 키를 가진 사업자 누구나 사용할 수 있으며 여러 법인을 지원합니다. macOS 11 이상에서 Apple Silicon과 Intel 모두 지원합니다. Python이나 Rust는 필요하지 않습니다.

## 설치와 설정

```sh
brew install DongeunPaeng/tap/davinci-bolta
davinci-bolta configure
```

처음 설정할 때 아래 안내에 따라 같은 법인의 live 키와 test 키를 입력합니다. 입력한 키는 화면에 표시하지 않습니다.

```text
볼타에서 받은 API KEY 2종(live, test)을 입력해주세요.
live API KEY:
test API KEY:
```

등록된 발급자의 상호, 사업자등록번호와 대표자명을 조회하고, 세금계산서에 표시되는 발행인 정보를 먼저 보여줍니다. 발급자가 여러 개면 번호로 선택합니다. 주소, 업태, 종목이나 담당자 정보가 기존 설정에 있으면 함께 보여줍니다. 발행 법인 담당자 이메일이 없으면 한 번 입력합니다. 기존 발행 기록이 있으면 해당 계산서의 발행인 정보로 이메일과 주소 등을 복원합니다.

등록된 발급자가 두 키 모두에 없으면 법인 정보를 한 번 입력하고 `davinci-bolta setup`으로 발급자와 공동인증서를 등록하세요. 두 키가 서로 다른 법인의 발급자를 가리키면 저장하지 않습니다.

키를 추가하고 `1. 다른 법인의 API KEY 추가`를 선택하면 여러 법인의 키를 연속 등록합니다. 기존 키는 Enter로 재사용할 수 있습니다. 발행 법인이 여러 개면 실행할 때 번호로 선택하며, `0. API KEY 추가`로 새 법인도 연결할 수 있습니다.

압축 파일을 사용하는 경우 압축을 풀고 해당 폴더에서 `sh install.sh`를 실행하세요.

## 고객 선택과 발행

```sh
davinci-bolta
```

```text
저장한 고객을 선택하거나 새 고객을 입력해주세요.
  0. 저장된 고객
  1. 새 고객 입력
```

고객 번호는 0부터 자동으로 배정하고 저장합니다. 이름이나 목록 순서가 바뀌어도 기존 번호는 유지됩니다. 사용자가 고객 번호를 정하는 단계는 없습니다. 새 고객 입력 항목은 항상 다음 번호를 사용합니다.

새 고객은 사업자등록번호를 입력하면 상호, 대표자명, 주소, 업태와 종목을 볼타에서 조회해 채웁니다. 번호가 일치하는 상세 조회 결과만 사용합니다. 정보가 없거나 대표자명이 가려져 있으면 필요한 항목만 직접 입력합니다. 공개 연락처 이메일을 세금계산서 수신 이메일로 자동 사용하지 않습니다.

고객을 정한 다음 빈 줄과 아래 안내문을 표시합니다.

```text
발행하실 세금계산서 내용을 적어주세요.
```

고객사 세금계산서 수신 이메일, 공급가액, 품목을 입력합니다. 저장된 이메일과 품목은 Enter로 재사용할 수 있습니다. 작성일은 오늘, 목적은 청구, 세금은 과세 10%가 기본값입니다. 마지막 화면에서 아래 메뉴를 번호로 선택하세요.

```text
1. 테스트
2. 발행(live)
3. 수정
4. 취소
```

Enter는 취소입니다. 테스트는 test 키, 발행(live)은 live 키를 사용합니다. `--mode test` 또는 `--mode live`를 명시하면 해당 모드의 항목만 실행할 수 있습니다.

## 고객사 조회와 테스트

실제 고객사 자동 조회에는 등록된 live 키를 사용합니다. 조회 성공마다 볼타 90포인트가 차감됩니다. 조회값은 Mac에 보관해 같은 번호를 반복 조회하지 않습니다. 저장된 고객 선택에는 조회 비용이 없습니다. 조회 실패나 포인트 부족 시 직접 입력할 수 있습니다.

무료 모의 조회와 테스트 발행을 함께 시험하려면 아래 명령을 사용하세요.

```sh
davinci-bolta --mode test
```

사업자등록번호 `1000000014`는 볼타가 제공하는 모의 사업자입니다. 테스트 키는 실제 사업자 데이터를 읽지 않고 모의 데이터만 반환하며 포인트를 차감하지 않습니다. 모의 조회로 등록한 고객사를 live 발행에 사용하는 것은 막습니다. 모의 데이터로 조회한 결과와 실제 조회 결과의 캐시도 구분합니다.

## 기존 설치의 마이그레이션

```sh
brew update
brew upgrade davinci-bolta
```

기존 키를 삭제하거나 configure를 다시 실행할 필요가 없습니다. 한 종류의 키만 저장된 사용자도 기존 기능을 계속 사용할 수 있습니다. 빠진 키는 그 모드의 기능을 선택할 때만 한 번 입력합니다.

법인 설정 파일이 없는 구버전은 davinci-bolta를 한 번 실행하면 저장된 키로 발급자 정보를 조회해 설정을 자동 복원합니다. 기존 법인 ID와 원장 연결은 유지합니다. 담당자 이메일은 기존 설정이나 이미 발행한 계산서에서 복원하며, 복원할 정보가 없는 경우에만 입력받습니다.

번호가 없는 기존 고객에게는 0부터 번호를 한 번 배정하고 기존 정보는 유지합니다. 변경 전 파일은 `~/.local/share/bolta-cli/backups/before-3.3.0`에 권한 `600`으로 보관합니다. 잘못된 키, 서로 다른 법인의 키, 조회 실패나 취소 때문에 기존 키와 법인 설정을 덮어쓰지 않습니다. 기존 CSV와 발행 기록은 재발행하지 않습니다. 키를 교체해도 이전 접수 건은 원래 키로 조회합니다.

## CSV와 상태 조회

```sh
davinci-bolta status
davinci-bolta validate invoices.csv
davinci-bolta --mode test issue invoices.csv --send
davinci-bolta --mode live issue invoices.csv --send --confirm-live
```

CSV 명령, 법인 ID, 기존 키 변수와 파일 경로는 계속 지원합니다. CSV 발행의 기본 모드도 기존 `BOLTA_API_MODE`를 유지합니다. `validate`는 API 요청 없이 검증합니다. CSV live 발행에는 `--send`와 `--confirm-live`가 필요합니다.

## 데이터와 서명

키, 법인과 고객 정보, 조회 캐시, 입력 CSV, 원장은 `~/.local/share/bolta-cli`에 보관합니다. 키와 데이터 파일은 권한 `600`으로 저장합니다. Homebrew 업그레이드나 삭제 시 데이터는 지우지 않습니다. 배포본에는 특정 법인 설정이나 실제 API 키, 고객 정보가 없습니다.

입력과 결과 CSV는 보관하되 경로, 서버 주소, 인증서 만료일과 접수 키는 출력하지 않습니다. 최종 발행 결과와 오류는 표시합니다. 같은 내용의 기존 건이 있으면 기존 상태 확인, 별도 청구로 새 발행, 취소 중 번호로 선택합니다.

실행 파일은 Developer ID Application 인증서로 서명했습니다. Apple 공증은 적용하지 않았습니다.

공식 문서: [사업자 프로필 조회](https://docs.bolta.io/docs/api-introduction/business-profile), [발급자 목록 조회](https://docs.bolta.io/api-reference/issuer/list-issuers).
